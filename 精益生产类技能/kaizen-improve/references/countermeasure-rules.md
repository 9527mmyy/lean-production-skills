# 对策规则

## 一、先分清真浪费与必要缓冲

这是最常被跳过的一步，也是最容易出错的一步。

| 现象 | 必要条件时才成立的解释 | 定性 |
|---|---|---|
| 工位旁堆料 | 批量配送、待检缓冲、换型备料 | 必要缓冲，问题在前道或检验周期 |
| 人员走动多 | 多机台看管、跨工位协同作业 | 作业设计如此，看走动是否可并 |
| 库存高 | 订单波动大、供应周期长 | 战略库存，要看资金成本 |
| 设备停机等待 | 瓶颈下游、单件小批 | 若瓶颈不在此前工序则属正常排队 |

判定口径：**能在一个节拍内消化掉的量是必要，超出的部分是浪费。** 没有节拍数据就不下这条结论。

## 二、3M 因果顺序

过载产生不均，不均产生浪费。

本能反应是去处理看得见的浪费（堆料、走动、等待），纪律是先修上游的过载和不均。堵住浪费现象而放过过载源，改善会反复。

排查顺序：
1. **MURI 过载**：哪道工序负荷超出生理或设备能力？谁在赶、谁在等？
2. **MURA 不均**：班次之间、人员之间、时段之间产出波动多大？波动源是什么？
3. **MUDA 浪费**：前三步做完，剩下的才是可消除的浪费。

## 三、七大浪费的现场辨认

| 浪费 | 照片里能看到的形态 |
|---|---|
| 过量生产 | 成品堆积、待入库区满、按预测而非订单生产 |
| 库存 | 在制品落地、容器层叠、无标识混放 |
| 搬运 | 料架离工位远、需二次转运、叉车频繁进出 |
| 等待 | 人员静止看设备、上下游之间断流 |
| 动作 | 弯腰取件、跨步转身、重复伸手、工具不在手边 |
| 过度加工 | 重复检验、去毛刺后再次修整、超规格加工 |
| 不良 | 返修区、红牌区、待处理标识 |

动作浪费与过度加工多需视频或现场跟班才能确认，照片只能提假设。

## 四、对策排序

按投入从低到高，不按效果从大到小。理由是先做零投入项能建立信任，且常能消掉一半问题。

1. **取消**：这道工序/这个动作能不能不做
2. **合并**：能不能与相邻动作或工序并做
3. **重排**：换顺序能否消除往返
4. **简化**：前三条都不行，再谈怎么做得更省力
5. **投资**：工装、设备、自动化，放最后

ECRS 顺序不能颠倒。跳过前四步直接上设备，是把管理问题用资本开支掩盖。

## 五、每条对策必须带三样

- **判定依据**：引用 A 档的具体事实，不能是"一般来说"
- **预期效果**：没有量化数据时写方向（减少搬运距离、缩短找料时间），不给百分比
- **验证方式**：怎么确认有效？谁在什么时候看？

缺验证方式的对策不要提。改善没有验证环节就不是改善，是建议。

## 六、不做的对策

- 加强考核、提高意识、加强培训 —— 无具体动作，等于没做
- 增加检验、加强把关 —— 用检验掩盖变异源
- 买设备解决布局问题 —— 投入大且不解决根因
- 要求操作者"注意一下" —— 把系统问题转成个人责任

这四类在国内工厂的改善提案里出现频率极高，识别出来要直接指出为什么无效，而不是换个说法包装。

## 七、改善后验证判据

每条对策落地后必须验证，否则改善没闭环。按对策级别给验证方法，缺对应数据就不写验证结论。

| 级别 | 验证方法 | 判定有效的条件 | 观察期 |
|---|---|---|---|
| 1 划线定置 | 改善前后各拍一张同角度照片；次日 + 次周各复查一次 | 次日无回潮，次周无回潮 | 两周 |
| 2 标识目视化 | 异常注入：故意放一件错位/超上限的件，记录从放置到被发现的时间 | 正常班次内（当班）被现场人员主动发现并纠正 | 一周 |
| 3 容器料架 | 改善前后各测一次取放时间（同一个人、同一批件、连续 5 次取放）；拍照对比 | 取放时间缩短，且容器无混放、无落地 | 两周 |
| 4 布局流程 | 改善前后各走一遍物流路径，记录步数或秒表时间；连续 5 个工作日观察 | 路径长度缩短且无新增交叉/回流；一周内无回潮 | 一周 |

- 验证时只对比同口径：同一个人、同一时段、同一品种。换人、换班次、换品种的数据不拿来对比。
- 照片对比必须同角度同距离，否则尺寸失真。
- 一周内没回潮才写"有效"。写"已改善"不算结论，要写"验证有效"或"未通过验证"。
- 5 级（设备投入）不做，不给验证方法。

## 八、输出量化收益的前提

只有在以下条件全部满足时才给数字：

1. 有批量与班产实测
2. 有节拍或循环时间（标定过的，非抽帧推算）
3. 有现状与改善后的对比口径
4. 涉及人力的，确认人员可重新配置而非仅"看起来省了"

缺任一条，只给方向与验证方法，不给金额。
