# 追问树

缺 C 档时用。一轮最多五条，问最少的能定性的问题。

## 提问顺序原则

先问批量与频次，再问约束，最后问已试过的方案。原因是前两者决定定性，后者只影响对策选择。

不要问拍摄者已经答过的，也不要问"你觉得哪里有问题"——那是把判断推回给用户。

## 一、在制品量是否合理

```
在制品堆在这里
├─ 每批多少件？一个容器装多少？
├─ 上下游之间是连续供料还是批量配送？
│   ├─ 连续供料 → 堆量超过 1 个容器即为多余 → 库存浪费
│   └─ 批量配送 → 继续问
│       ├─ 是待检缓冲还是工序间缓冲？
│       │   ├─ 待检缓冲 → 查检验周期，缩短周期比减堆量有效
│       │   └─ 工序间缓冲 → 查前后节拍差
│       └─ 缓冲量是谁定的？有标准吗？
└─ 这批料放了多久？（超 8 小时基本可判为积压）
```

定性分界：**能在一个节拍内消化掉的量是必要缓冲，超出的部分是浪费。** 没有节拍数据时无法划这条线。

## 二、通道占用是否成立

```
物品在通道上
├─ 地面上有定置线吗？
│   ├─ 有，物品在线外 → 定置违规，事实清楚，可直接定性
│   └─ 无定置线 → 布局本身缺标准，问题在管理基础不在这个物品
├─ 占用是长期还是临时？
│   ├─ 长期（每天每班都在）→ 面积不足或布局错误
│   └─ 临时（换型、待检、来料集中）→ 查触发条件，做临时存放点
└─ 通道被占后，人和车怎么走？绕行距离多少？
```

## 三、目视化缺失的严重度

```
看不到标准
├─ 是完全没有，还是有过期版本？
├─ 新人能不能靠现场信息独立作业？
├─ 异常发生时，多远距离能发现？
└─ 参数、件号变了，标识多久更新一次？
```

判据：**目视化的目的是让异常一眼可见。** 如果异常只能靠人跑去查，缺的不是标识牌，是异常响应机制。

## 四、5S 是习惯问题还是设施问题

```
现场乱
├─ 有没有地方放？（定置区是否足够）
│   ├─ 没地方放 → 设施/面积问题，靠考评解决不了
│   └─ 有地方不放 → 习惯问题，查为什么不便
├─ 取用和归位是否一步到位？需要弯腰、跨越、开柜吗？
└─ 班末有无清理时间？谁负责？
```

判据：**归位比随手放更费劲时，5S 一定退回去。** 先改设施，再谈素养。

## 五、堆码不整齐是能力问题还是标准问题

```
堆码混乱
├─ 同区域有没有"整齐"的托盘？
│   ├─ 有 → 能整齐但没标准，问题在管理不在能力
│   │   └─ 对策落 1 级（摆整齐）+ 2 级（贴标准卡）
│   └─ 没有 → 查原因
│       ├─ 件体尺寸超过托盘 → 容器不匹配，归 3 级（换料架）
│       ├─ 堆叠限高不清楚 → 缺标准，补 2 级
│       └─ 搬运方式导致（叉车一次叉两件）→ 作业设计问题，查 4 级
├─ 堆码标准是什么？
│   ├─ 同向平行 / 端头齐线 / 不超托边 / 限高 X 层
│   └─ 标准是谁定的？操作者参与了吗？
└─ 堆叠上限几层？现在超了吗？
    ├─ 没定上限 → 先定标准（2 级）
    └─ 定了但超了 → 查为什么超（批量大了？托盘小了？限高不合理？）
```

判据：**堆码四条标准——同向、齐边、不突出、限高。** 缺一条就算不整齐。"能整齐但没标准"和"真的做不到"是两种问题，对策不同：前者贴标准卡，后者换容器。

## 六、过载与不均（MURI / MURA 诊断）

MUDA 追问之前先过这一层。堆积、等待、赶工大多是 MURI/MURA 的结果，直接去处理浪费现象会反复。

```
这个工位总是赶工 / 堆料 / 等料
├─ 等料多还是干不完多？
│   ├─ 等料多 → 瓶颈不在本工位，在前道或供料
│   │   ├─ 前道是哪个工序？它的负荷是不是超了？
│   │   └─ 供料是连续还是批量？批量配送的间隔是不是太长？
│   └─ 干不完多 → 本工位是瓶颈或能力不足
│       ├─ 是设备能力不够还是人员动作慢？
│       └─ 多品种共线时，换型时间占了多少？
├─ 班次之间产出差异大吗？
│   ├─ 大 → 查差异源：人员熟练度、设备状态、来料质量
│   └─ 小 → 波动不来自这里，往上下游查
└─ 你怎么判断瓶颈工序的？
    ├─ 凭感觉 → 补 C 档：每道工序的实测节拍、在制品量
    └─ 有数据 → 瓶颈工序的负荷是否超过设备或人员能力上限？
```

判据：**先修过载，再修不均，最后才是浪费。** 不画 VSM、不画山积图，只靠观察和追问做定性诊断。定量诊断（节拍、线平衡）需要完整工序表，本库不做。

## 六、改善是否已经试过

```
├─ 试过什么？结果如何？
├─ 为什么没维持住？（这是最有价值的一问）
└─ 谁决定的标准？操作者参与了吗？
```

没维持住的原因通常是：标准由办公室定、未考虑实际作业节拍、无人复核。这三条决定了对策该落在哪。

## 收尾

五问之后仍有缺口，直接写进 C 档，不要用假设填空。宁可结论少一条，不要结论错一条。
