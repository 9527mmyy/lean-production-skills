# 流程程序图标准（Process Chart）字段与统计口径

本文件定义 `build_report.py` 实际生成的《流程程序图》结构。字段、列号与代码必须与脚本一致；`assets/动作分析问题项及改善表单模板.xlsx` 是由脚本生成的空白模板，结构与本文完全相同。

---

## 1. 整体布局

- 数据区 **B–T 共 19 列**，加 A 列窄边距、U 列图例，合计 21 列。
- 标题：B2:T2 合并，`<产品>产品流程程序图　　时间：<日期>`。
- 表头：第 3–4 行两级，第 5 行起为数据行。
- 统计不占顶部独立区域，统一放在合计行（见 §5）。

## 2. 表头信息区

| 单元格 | 字段 | 数据来源（meta） |
|---|---|---|
| B3 / C3 | 图号 | `drawing_no` |
| B4 / C4 | 研究人员 | `researcher` |
| B5 / C5 | 人力 | `manpower` |

## 3. 两级表头（第 3–4 行）

| 列 | 字段 | 合并方式 | 来源字段 |
|---|---|---|---|
| B | 序号 | B3:B4 | `actions[].seq` |
| C | 作业内容 | C3:C4 | `content` |
| D | 搬运距离（m） | D3:D4 | `distance` |
| E | 时间（S） | E3:E4 | `time` |
| F–J | 符号（F3:J3 合并标题）→ F操作○ / G搬运→ / H暂存Ｄ / I检查□ / J储存▽ | 各自独立 | `symbol` |
| K | 有价值作业（◎） | K3:K4 | `value=V` |
| L | 无价值作业（●） | L3:L4 | `value=N` |
| M | 无价值但必须进行作业（○） | M3:M4 | `value=M` |
| N | 问题描述 | N3:N4 | `problem` |
| O–R | 改善方法（O3:R3 合并标题）→ O取消E / P合并C / Q重排R / R简化S | 各自独立 | `ecrs` |
| S | 改进建议 | S3:S4 | `suggestion` |
| T | 备注 | T3:T4 | `remark` |
| U | 符号图例（U3:U10，8 行） | — | 固定 |

说明：ECRS 的**列字母**是 O–R（第 15–18 列），与代码 `E`/`C`/`R`/`S` 是两套符号，不要混淆。

## 4. 数据行规则

- 每个动作一行，序号从 1 递增。
- 符号：F–J 五列中只选一列填对应字符（○/→/Ｄ/□/▽）。
- 价值：K–M 三列中只选一列填对应字符（◎/●/○）。
- 改善方法：O–R 四列中只选一列填 `E`/`C`/`R`/`S`；无改善项留空。
- 问题描述（N）、改进建议（S）、备注（T）各自独立成列，直接写值，不使用跨列合并。
- 改进建议与备注同时存在时两列都保留，互不覆盖。

## 5. 合计行（12 类计数）

末行 C 列写"合计"。D、E 列为公式：

- D = `SUM(D5:D<末行前>)`
- E = `SUM(E5:E<末行前>)`

计数全部为静态值：

| 类别 | 列 | 计数内容 |
|---|---|---|
| 符号 | F–J | 操作○/搬运→/暂存Ｄ/检查□/储存▽ 各计一次 |
| 价值 | K–M | 有价值◎/无价值●/无价值但必须○ 各计一次 |
| ECRS | O–R | 取消E/合并C/重排R/简化S 各计一次 |

合计行计数由脚本统计，等于明细统计结果；HTML 报告的 12 张统计卡使用同一份计数。

## 6. 与问题项检查表的联动

流程程序图中判定为「无价值●」或填写了问题描述/改善方法的行，应同步登记到《问题项检查表》：

- 作业内容 → B 列「作业/动作描述」
- 主导动素 → C 列「动素」
- 符号与价值 → 辅助判断 D 列「问题类别」
- 问题描述 → E 列「问题描述」
- 时间/频次 → F、G 列
- 浪费类型、严重度、责任人、改善状态按 `ie-toolkit.md` 判定

## 7. 输出一致性要求

- xlsx 与 html 两种交付物的动作序号、作业内容、时间、距离、符号、ECRS、计数必须一致。
- HTML 图例与 U 列图例一致，颜色仅用于区分：有价值（绿）、无价值（红）、无价值但必须（黄）。
- 合计行计数等于明细统计结果；D、E 列 SUM 公式覆盖全部数据行。
