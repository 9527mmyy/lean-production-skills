# 拍摄、验证与数据保护指南

本文件分三部分：§1 拍摄纪律（Step 1 前置检查）、§2 交叉验证（Step 7 交付质检）、§3 隐私与数据保护（红线）。

---

## §1 拍摄纪律

### 1.1 硬性要求（不满足则提示用户补拍，不要硬猜）

| # | 要求 | 原因 |
|---|------|------|
| 1 | 固定三脚架，机位不动 | 帧间对比才有意义，晃动导致变化点检测失效 |
| 2 | 俯拍（≥45° 俯角） | 能同时看到操作员双手、工具、工件、物料流向 |
| 3 | ≥5 个完整循环 | 少于 5 个无法算均值，工时统计无统计意义 |
| 4 | ≥1080p | 720p 以下小动作（如拧螺丝、调表）看不清 |
| 5 | 整个作业区域在画面内 | 不能只拍手部，要包含物料取放位置、设备操作区 |
| 6 | 光线充足，无逆光 | 逆光导致画面偏暗，动作边界不清 |
| 7 | 手机/相机横拍 | 竖拍画面窄，两侧作业区域被裁掉 |

### 1.2 拍摄前检查清单（用户自查）

- [ ] 三脚架固定，镜头俯拍 ≥45°
- [ ] 画面覆盖整个作业区域（含物料取放、设备操作区）
- [ ] 光线充足，无逆光、无阴影遮挡
- [ ] 手机横拍，≥1080p
- [ ] 至少 5 个完整循环（从第一个动作到最后一个动作，循环之间无长停顿）
- [ ] 操作员着装整洁（不露脸也可，但要能分辨操作员）
- [ ] 作业区域内无无关人员走动
- [ ] 录制前确认存储足够（1080p 约 120 MB/分钟）

### 1.3 常见错误

| 错误 | 后果 | 纠正 |
|------|------|------|
| 手持拍摄 | 画面晃动，变化点检测误报率高 | 必须用三脚架 |
| 平拍（与桌面同高） | 看不到物料流向和搬运路径 | 改用俯拍 |
| 只拍手部特写 | 看不到整体作业布局和搬运距离 | 拉远镜头覆盖全区域 |
| 循环间长停顿（>30s） | 时间轴断裂，循环划分困难 | 循环间停顿 <10s，或标记循环边界 |
| 竖拍 | 画面窄，两侧被裁 | 横拍 |
| 720p | 小动作看不清 | ≥1080p |
| 逆光 | 画面偏暗，动作边界不清 | 调整机位或补光 |

### 1.4 视频元信息确认

抽帧前用 ffprobe 确认：

```bash
ffprobe -v quiet -print_format json -show_format -show_streams "视频.mp4" 2>/dev/null | python -c "import sys,json; d=json.load(sys.stdin); f=d['format']; s=[x for x in d['streams'] if x['codec_type']=='video'][0]; print(f'Duration: {float(f[\"duration\"]):.1f}s'); print(f'Resolution: {s[\"width\"]}x{s[\"height\"]}'); print(f'FPS: {s[\"r_frame_rate\"]}')"
```

- 时长 < 5 个循环（按作业节拍估算）→ 提示补拍
- 分辨率 < 1080p → 提示补拍
- FPS < 15 → 提示补拍（帧数太少，动作边界不清）

## §2 交叉验证

### 2.1 目的

视频帧分析是间接观测，存在帧率损失、视角盲区、动作边界误判等误差。交叉验证通过手动计时独立测量，验证分析结果的准确性。

**首次分析必做。** 后续同一作业的视频分析可跳过（除非视频条件发生重大变化）。

### 2.2 验证流程

1. **手动计时**：用秒表（手机计时器即可）对视频中的 3 个完整循环逐元素计时
   - 回放视频，逐元素记录起止时间
   - 每个元素记 3 次（3 个循环）
   - 记录到临时表格（元素名 / 循环1 / 循环2 / 循环3 / 均值）

2. **对比**：将手动计时均值与分析结果（analysis JSON 中对应动作的时间值）逐元素对比
   - 偏差 = (手动均值 - 分析值) / 手动均值 × 100%
   - 逐元素计算偏差

3. **接受门**：
   - 单元素偏差 ≤ ±5% → 通过
   - 单元素偏差 > ±5% 但 ≤ ±15% → 标记"需复查"，在报告中注明
   - 单元素偏差 > ±15% → 不通过，排查原因
   - 总时间偏差 ≤ ±5% → 通过
   - 总时间偏差 > ±5% → 不通过，排查原因

4. **不通过排查**（§2.2 排查表）：

| 可能原因 | 排查方法 | 纠正 |
|---------|---------|------|
| 帧率损失 | 检查动作起始/结束帧是否准确（前后各看 1-2 帧） | 调整动作边界 |
| 视角盲区 | 检查动作是否在画面边缘被裁切 | 重新分析该动作 |
| 循环划分错误 | 检查循环起止点是否正确 | 重新划分循环 |
| 手动计时误差 | 重新计时一次 | 取两次均值 |
| 视频本身有问题 | 检查视频是否掉帧、卡顿 | 提示用户补拍 |

5. **验证记录**（写入 HTML 报告"七、流程程序图明细"之后，或单独一节）：

```
交叉验证记录：
- 验证日期：YYYY-MM-DD
- 验证循环数：3
- 逐元素偏差：（表格：元素 / 手动均值 / 分析值 / 偏差%）
- 总时间偏差：X%（手动 XX.Xs / 分析 XX.Xs）
- 结论：通过 / 需复查 / 不通过
- 备注：（如有偏差 >5% 的元素，说明原因和处理）
```

### 2.3 验证记录格式

在 HTML 报告中增加一个折叠区块（`<details>`），标题"交叉验证记录"，内含：
- 验证日期
- 验证循环数
- 逐元素偏差表格（元素名 / 手动均值 / 分析值 / 偏差%）
- 总时间偏差
- 结论（通过/需复查/不通过）
- 备注

## §3 隐私与数据保护

### 3.1 红线清单（不可逾越）

| # | 红线 | 说明 |
|---|------|------|
| 1 | 视频不上传外部 | 不上传到任何第三方平台、不发送给外部人员 |
| 2 | 报告不含可识别个人信息 | 操作员用"操作员A/B"代替，不含姓名、工号、工牌 |
| 3 | 分析结果仅用于工艺改善 | 不用于绩效考核、劳动纪律检查等人事目的 |
| 4 | 原始视频用后删除 | 报告确认后删除原始视频和抽帧图片 |
| 5 | 不录制非作业时间 | 只录作业循环，不录休息、闲聊等 |

### 3.2 拍摄前告知

- 告知操作员正在录制视频用于工艺分析
- 说明视频仅用于改善评审，不用于考核
- 征得操作员同意（口头即可，但建议有记录）

### 3.3 分析中处理

- 视频在本地处理（本机抽帧、分析），不经过任何外部服务
- 抽帧图片在本地生成，不上传
- 分析结果（JSON、Excel、HTML）在本地生成
- 如用 AI 视觉分析（subagent），只传 contact sheet 图片，不传完整视频

### 3.4 分析后清理

- 报告确认后，删除：
  - 原始视频文件
  - 抽帧帧图片（frames/ 目录）
  - contact sheet 图片（contact_sheets/ 目录）
  - manifest.json
- 保留：
  - 分析数据 JSON
  - 交付物（xlsx + html）
  - 交叉验证记录（在 HTML 报告中）

### 3.5 数据归属

- 视频、抽帧、分析数据、报告均归公司所有
- 不对外分享原始视频或含操作员可识别信息的材料
- 报告如需分享给外部（如客户、顾问），先脱敏（去操作员信息、去具体产品型号如涉密）
